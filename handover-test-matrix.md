# ERP Handover Test Matrix

## Purpose

This matrix defines the checks required for operational handover of the Al Hussam Tailor ERP. It separates repository-verified behavior from live-browser behavior. An authorized owner session reached the protected workspaces and verified the core read-only workflows. A controlled POS-to-tailoring transaction was confirmed through read-only production records after the browser timed out; remaining mutation, printing, and role-specific checks remain operator acceptance items.

## Automated baseline

After the local-auth migration changes, `pnpm check` passed. The full Vitest suite and both the standalone backend build and static Vercel build are release gates and must be rerun before deployment.

## Live-test limitation

The authorized production session opened the protected dashboard and the core Customers, Inventory, Tailoring Orders, Sales History, POS, Invoices, Staff & Payroll, Shop Settings, and Audit workspaces. Read-only checks passed for existing customers, meter/roll inventory display, service catalog visibility, POS catalog controls, customer selection, and customer/cart synchronization. A controlled connected tailoring order was then confirmed in production with order `TO-1787199224117`, sale `POS-TO-1787199224117`, invoice `INV-000021`, payment `48.000 BHD` cash, and linked material movement from `8.000` to `5.000` meters. The browser timed out after submission, so no duplicate transaction was attempted. Password-email completion, role boundary testing, normal POS checkout, returns/exchanges, payroll writes, staff-document upload, invoice printing, settings writes, and full production-stage progression remain operator acceptance steps.
